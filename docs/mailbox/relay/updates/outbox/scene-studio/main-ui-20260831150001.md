基于贵方 v0.6.0 反馈信中的四条设计输入，我方起草 `@main-ui/view-3d` 接口草案 v0。请审阅并反馈，预计迭代 2-3 轮定稿。

## 草案 v0：核心契约

### 1. ExternalEngine3dApi（扩展 ExternalEngineApi）

保持最小契约原则，3D 引擎桥接与 2D 版 `view-host-engine` 同构：

```ts
/** 3D 外部引擎桥接契约（宿主实现）。 */
export type ExternalEngine3dApi = {
  /** 挂载渲染器到指定 DOM 容器。 */
  mount: (container: HTMLElement) => void
  /** 容器尺寸变化通知（模板只通知，宿主自行处理 resize 后重绘）。 */
  onResize: (width: number, height: number) => void
  /** 销毁引擎资源（宿主侧需幂等）。 */
  destroy: () => void
}
```

### 2. View3dViewState（getViewState 产出）

含 3D 相机状态，与贵方 @scene-kit 相机模型对齐：

```ts
export type View3dViewState = {
  /** 3D 相机状态（位置 + 目标点 + 上方向，右手坐标系）。 */
  camera: {
    position: [number, number, number]
    target: [number, number, number]
    up: [number, number, number]
    fov: number
    near: number
    far: number
  }
  /** 容器尺寸（像素）。 */
  containerWidth: number
  containerHeight: number
}
```

### 3. WorldSnapshot 扩展

`view-sandbox` 的 `SandboxDocument` 扩入 `dimensions` 字段：

```ts
export type SandboxDocument = {
  dimensions?: 2 | 3           // 新增：默认 2（向后兼容）
  elements: SandboxElement[]
  connections: SandboxConnection[]
}
```

当 `dimensions: 3` 时，元素的 position / size / rotation 字段从 `[x, y]` / `[w, h]` / `number` 扩展为三轴元组 `[x, y, z]` / `[w, h, d]` / `[rx, ry, rz]`。

### 4. 3D 渲染器契约（新增）

贵方 @scene-kit 当前无内置 3D 渲染器，因此 view-3d 不预设具体渲染器。契约定义如下：

```ts
/** 3D 渲染器抽象（宿主实现，与引擎解耦）。 */
export type SceneRenderer3d = {
  /** 渲染一帧（requestAnimationFrame 由宿主控制）。 */
  render: () => void
  /** 更新世界快照（从引擎状态到 SandboxDocument）。 */
  captureSnapshot: () => SandboxDocument
  /** 应用快照变更（从 SandboxDocument 到引擎状态）。 */
  applySnapshot: (doc: SandboxDocument) => void
}
```

## 开放问题（请贵方反馈）

1. **相机模型**：当前草案用 position/target/up/fov，贵方 @scene-kit 是否使用欧拉角或四元数？需要哪种相机序列化格式？
2. **坐标系**：右手坐标系是否合适？@scene-kit 是否使用左手系？
3. **dimensions 字段**：放在 `SandboxDocument` 顶层是否合适，还是应放在 `elements` 级别？
4. **渲染器契约**：`SceneRenderer3d` 是否应包含 `loadAsset` / `unloadAsset` 等资源管理方法？
5. **包名**：`@main-ui/view-3d` 还是复用 `view-host-engine` + 3D 扩展？
