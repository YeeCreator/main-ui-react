# support advice (updates-outbox): main-ui -> matheshop

## Subject: KaTeX × view-2d 自定义图层联合设计邀请

基于贵方 v0.6.0 反馈信（批次 4 评估完成：view-2d 已装，KaTeX 接入待联合设计），我方发起 KaTeX 数学公式与 view-2d 画布的联合设计方案讨论。

## 背景

贵方 matheshop 同时依赖 `katex`（数学公式渲染）和 `viewport-2d-kit`（2D 画布引擎）。当前 view-2d 模板只提供相机/视口底座（`onReady` 回调拿到 `PixiViewport` 后宿主自行绘制），数学公式的画布内嵌是典型的高频场景。

## 联合设计方向（初步）

### 方案 A：KaTeX 作为 PixiJS Sprite 纹理

把 KaTeX HTML 渲染为离屏 canvas → 转为 PixiJS Sprite 纹理 → 放入视口世界坐标系。

- **优点**：公式成为世界坐标中的对象，可平移/缩放/旋转，与视口交互一致。
- **缺点**：公式是位图，缩放时可能模糊；需要重新生成纹理以更新。
- **适用**：公式作为画布上的固定标注。

### 方案 B：KaTeX HTML Overlay（视口坐标系映射）

KaTeX 渲染为 DOM 元素，通过 viewport-2d-kit 的世界坐标 → 屏幕坐标映射，叠加在画布上层。

- **优点**：公式始终清晰（矢量渲染），缩放时自动更新位置。
- **缺点**：DOM 层与 PixiJS 层需要坐标同步；大量公式时 DOM 性能瓶颈。
- **适用**：公式作为交互式标注（需要选中、编辑）。

### 方案 C：混合模式

公式分两类：静态标注走方案 A（纹理），交互式公式走方案 B（DOM overlay）。view-2d 模板不感知 KaTeX，但 viewport-2d-kit 提供「世界坐标 DOM overlay 锚点」能力（新增）。

## 我方建议

推荐 **方案 C**（混合模式）。理由：

1. viewport-2d-kit 新增 `WorldAnchor` API（世界坐标 → DOM 锚点映射），这是一个通用能力，不只服务 KaTeX。
2. view-2d 模板不需要改动（保持薄封装），KaTeX 集成逻辑留在宿主适配层。
3. 静态标注纹理化方案可由宿主自行实现（PixiJS 原生支持 `PIXI.Texture.from(canvas)`）。

## 开放问题（请贵方反馈）

1. **公式交互需求**：画布中的公式是否需要支持选中、编辑、拖拽？还是纯展示？
2. **公式数量级**：典型画布中大约有多少个公式实例（十级/百级/千级）？
3. **实时更新**：公式内容是否需要实时编辑 → 画布内同步更新？
4. **方案偏好**：贵方倾向哪种方案？或有其他考虑？
