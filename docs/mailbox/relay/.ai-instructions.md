# mailbox/relay — AI 行为指引

你正在一个已接入 autodo 多项目联动治理体系的项目中工作。

## 信箱位置

`docs/mailbox/relay/`

## 功能分类（按类型划分）

| 目录 | 类型 | 含义 | 你何时写 | 你何时读 |
|------|------|------|----------|----------|
| `updates/outbox/` | 更新类 | 发给被依赖项目的适配建议 | **你修改了公共 API 后** | — |
| `feedback/outbox/` | 反馈类 | 发给上游项目的依赖反馈 | 你发现上游 API 有问题/有改进建议 | — |
| `updates/inbox/` | 更新类 | 上游发来的适配建议 | — | **每次会话开始时检查** |
| `feedback/inbox/` | 反馈类 | 下游发来的依赖反馈 | — | **每次会话开始时检查** |

## 触发规则

### 你必须主动写信的情况

1. **修改了公共 API**（函数签名、类接口、模块导出、配置字段）→ 在 `updates/outbox/` 为每个下游写适配建议
2. **废弃了旧接口** → 在 `updates/outbox/` 写明迁移路径和截止时间
3. **发现了上游依赖的 bug 或设计问题** → 在 `feedback/outbox/` 写反馈

### 你必须主动查信的情况

1. **每次会话开始时** → 快速扫描 `updates/inbox/` 和 `feedback/inbox/`，摘要汇报
2. **发版前** → 确认没有未处理的适配建议
3. **引入新依赖或升级依赖版本时** → 检查 `feedback/inbox/` 是否有相关通知

## 信件命名（带时间戳）

文件名为 `{项目ID}-{YYYYMMDDHHmmss}.md`，存放在对应项目的子文件夹中：
- `updates/outbox/{peerProjectId}/` — 写给下游的更新建议
- `feedback/outbox/{peerProjectId}/` — 写给上游的反馈
- `updates/inbox/{peerProjectId}/` — 来自上游的更新建议
- `feedback/inbox/{peerProjectId}/` — 来自下游的反馈

同一收件人的多封信件靠时间戳后缀区分，**不要覆盖已有信件**。

## 自助投递（写完后默认自己投递）

写完 outbox 信件后，**默认由你直接投递到对方 inbox**，无需等待统一投递：

1. 从 `registry.md` / `dependencies.md` / `support.md` 查到对方项目 ID 与路径。
2. 将信件复制到对方项目对应 inbox（保留带时间戳的文件名）：
   - 写给上游的反馈 → `{对方}/docs/mailbox/relay/feedback/inbox/{我方项目ID}/`
   - 写给下游的建议 → `{对方}/docs/mailbox/relay/updates/inbox/{我方项目ID}/`
3. 统一投递（deliver）仍可按内容 hash 去重，不会重复投递。

## 过期归档（每次任务结束时自动执行）

任务结束时，检查 inbox 中超过 180 天的信件（按 mtime），移入 `docs/mailbox/relay/archive/{peerId}/{mailboxType}/{date}-{peerId}.md`。可调用投递事务技能执行归档。
