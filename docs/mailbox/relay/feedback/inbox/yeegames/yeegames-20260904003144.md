## 发现事项 / 改进建议（走本反馈信道回流）

- **F-3（缺陷·高）view-sandbox 的 `getViewState` 返回响应式 Proxy，拖垮 `structuredClone` 持久化链**：
  `SandboxView.getViewState()` 返回 `camera: cameraState.value`（`ref(对象)` 的 `.value` 是 Vue 响应式 Proxy）。
  内核 `MainUiCoreRuntime.dispatch` 每次先 `workbenchReducer → cloneDocument = structuredClone(document)`，再
  `captureViewStates` 把 `getViewState()` 写入 `editor.viewState`。于是沙盘激活并发生一次 dispatch 后，文档内即驻留
  Proxy；**下一次任意 dispatch（切页签/切工作区/开关编辑器）在 `structuredClone` 处抛
  `DataCloneError: #<Object> could not be cloned`，工作台交互全面瘫痪**（浏览器实测稳定复现）。
  - 复现：注册 sandbox（传 editorInstanceId）→ 激活沙盘页签 → 再切任意页签/工作区。
  - 栈：`reducer.ts:19 cloneDocument` ← `reducer.ts workbenchReducer` ← `runtime.ts:173 dispatch`；`runtime.ts:227 captureViewStates` 写入 Proxy。
  - 根因：`MainUiViewLifecycle.getViewState` 契约要求可序列化（进快照并被 `structuredClone`），返回 Proxy 违约；
    其余模板均以 `[...]` / `{...}` 展开为普通值，唯独 sandbox 的 `camera` 未展开。
  - 建议修复：`getViewState` 返回 `camera: { ...cameraState.value }`（或 `toRaw(cameraState.value)`）。
  - 宿主侧规避（已落地）：改用薄壳 `LevelSandboxEditor.vue` 渲染 `SandboxView` 且**不传 editorInstanceId** → 不挂视图
    生命周期 → 不采集视图状态 → Proxy 不入文档；沙盘照常渲染/抛意图，仅相机/选中不持久化（试点可接受）。修复后可改回一键注册。
- **F-4（缺陷·中）view-table 的 `getViewState` 同类隐患（sort）**：`TableView.getViewState()` 返回 `sort: internalSort.value`；
  默认 `null`（普通值）安全，但用户一旦点击可排序列头，`internalSort.value` 变为响应式 Proxy，触发与 F-3 同样的 DataCloneError。
  - 建议修复：`sort: internalSort.value ? { ...internalSort.value } : null`。
  - 宿主侧规避（已落地）：游戏库表格暂不开启列 `sortable`，使 `internalSort` 恒为 `null`；修复后再开启排序。
- **F-1（建议）view-host-engine 无一键注册器**：与其余模板 `registerXxxViewEditor` 不一致，宿主须手写 descriptor + renderer
  包装（已在 `P5StageEditor.vue` 落地）。建议提供 `registerHostEngineViewEditor(runtime, options, resolveEngine)`，引擎实例经 context 注入。
- **F-2（建议）`registerXxxViewEditor` 的 options 不暴露 `capability`**：模板 descriptor 固定 `{...defaultEditorCapability, allowFloatingWindow}`，
  宿主无法把模板 editor 设为 `allowClose:false` 常驻导航（用 view-tree 替换自研常驻资源树时受限）。建议 options 增加 `capability?` 覆盖位。
- **附带发现（非缺陷）SandboxView 内置渲染 kernel**：视图自身 `createSandboxKernel(props.document)` 且 `watch(props.document, deep)→fromJSON`，
  故宿主作为文档单一事实源、意图裁决后不可变更新文档即可（对齐 demo 节点图范式），无需另建 host 侧 kernel。建议 PRESET_VIEWS_GUIDE §4.9 补一句说明。
