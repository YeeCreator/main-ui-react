## 3. 改造线批次 2 结果：view-host-engine 桥接 @scene-kit

### 实现方案

- 新增依赖：`@main-ui/view-host-engine@workspace:^0.6.0`
- 创建桥接器 `src/editors/sceneEngineBridge.ts`：实现 `ExternalEngineApi` 契约（`mount` / `onResize` / `destroy`），内部通过 `createApp` 将 `WorldViewport2D`（@scene-kit/renderer-2d）挂载到 HostEngineView 提供的 DOM 容器
- 创建编辑器 `src/editors/HostEngineViewportEditor.vue`：作为 `scene-host-engine-viewport` kind 注册，与原有 `scene-viewport` 并存
- 类型检查 + 构建：✅ 全绿

### 桥接架构

```
HostEngineView（main-ui）
  ├── DOM 容器 + ResizeObserver
  └── ExternalEngineApi.mount(container)
        └── createApp(WorldViewport2D)   ← @scene-kit/renderer-2d
              └── Viewport2DCanvas（viewport-2d-kit/vue）
                    └── Canvas 2D 渲染
```

### 关键设计决策

- **不走 viewport-3d-kit**（确认）：@scene-kit 场景引擎的 2D 渲染管线完全自洽，无需 React 兼容层
- **createApp 独立挂载**：桥接 Vue 组件树与主组件树隔离，通过 reactive getter 传递 snapshot / selected 数据
- **onResize 委托**：`WorldViewport2D` 内部的 `Viewport2DCanvas` 通过自身 ResizeObserver 响应尺寸变化，桥接器 `onResize` 仅作通知入口预留

## 5. 改造线批次 4 立场：@scene-kit ↔ view-3d 契约共研

scene-studio 确认参与批次 4 共研，以下为 @scene-kit 场景引擎接口现状与 view-3d 设计建议：

### @scene-kit 渲染管线现状

- **2D 渲染**：`@scene-kit/renderer-2d` → Canvas 2D API + `viewport-2d-kit/vue`（平移/缩放/fit）
- **数据流**：`WorldSnapshot`（协议化 JSON：entityBatches + relationBatches + world bounds）→ 渲染器消费
- **交互**：`select` / `move` 事件上抛 → `world.commands` 下派
- **无 3D 渲染器**：当前 @scene-kit 不含 3D 渲染管线；若 view-3d 要桥接 @scene-kit，需先定义 3D 渲染器契约

### view-3d 设计建议

1. **ExternalEngineApi 扩展**：当前 `mount(container)` / `onResize(w, h)` / `destroy()` 对 2D/3D 引擎均适用，建议保持此最小契约不变
2. **3D 相机状态**：view-3d 的 `getViewState` 应含 3D 相机（position / target / up / fov），与 view-host-engine 的容器尺寸状态不冲突
3. **场景数据格式**：@scene-kit 的 `WorldSnapshot` 是 2D 坐标（u/v）；3D 场景需扩展为 `world_x/world_y/world_z` 三轴，或增加 `dimensions: 3` 标志
4. **建议共研节奏**：先由 main-ui 出 view-3d 接口草案，scene-studio 基于 @scene-kit 3D 渲染器规划提供反馈，迭代 2-3 轮后定型

## 6. 发现事项（非缺陷，需 main-ui 知晓）

### 6.1 workspace 解析需补充 packages 路径（中等优先级）

`pnpm-workspace.yaml` 中 `"../main-ui"` 指向 main-ui monorepo 根（`"version": "0.0.0"`），而非 `"packages/main-ui"`（`"version": "0.6.0"`）。`workspace:^0.6.0` 无法解析到 `0.0.0`，需宿主侧额外声明 `"../main-ui/packages/*"` 才能正确解析。

**建议**：在 `HOST_INTEGRATION_GUIDE.md` 的 workspace 配置示例中明确说明 monorepo 宿主需把上游的 `packages/*` 路径一并加入 workspace，或提供 `file:` 协议替代方案文档。

### 6.2 旧主题变量仍在使用（低优先级）

scene-studio 的 `studio.css` 仍使用 `--main-ui-*` 旧变量名（如 `--main-ui-bg`、`--main-ui-text`、`--main-ui-border`）。迁移指南确认旧名仍兼容，无强制迁移。后续可逐步迁移到 `--mui-*` 新变量。
