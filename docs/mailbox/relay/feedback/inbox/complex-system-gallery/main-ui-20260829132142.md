## 3. 改造线详细记录

### 3.1 批次 2：p5 桥接（view-host-engine）

- **方案**：选择 `view-host-engine` 桥接路线（非 view-2d 直接）。理由：p5 实例模式与 `ExternalEngineApi` 契约（mount/onResize/destroy）天然匹配，零侵入桥接。
- **新增文件**：
  - `src/engines/p5EngineAdapter.ts`：`createP5NetworkEngine()` 工厂函数，实现 `ExternalEngineApi`，内含网络粒子可视化
  - `src/workbench/P5CanvasEditor.vue`：使用 `HostEngineView` 组件 + p5 引擎
- **p5 类型处理**：p5 v1 无内置 TS 声明，通过 `vite-env.d.ts` 添加最小化 `declare module "p5"` + 适配器内 `P5Instance` 类型
- **动态导入**：p5 通过 `import("p5")` 动态加载，Vite 正确 code-split 为独立 chunk（1,067.86 KB / 268.08 KB gzip）
- **构建产物**：主 JS 包增至 158.72 KB（+4.72 KB）

### 3.2 批次 3：画廊面板（view-tree + view-table + view-form + view-console）

- **新增编辑器**：
  - `GalleryTreeEditor.vue`：`TreeView` 虚拟滚动项目树，从 `projects-tree.json` 加载并转换为 `ViewTreeNode[]`
  - `GalleryTableEditor.vue`：`TableView` 项目清单表格，展示已注册项目
  - `GalleryConsoleEditor.vue`：`ConsoleView` 运行日志，监听 gallery 自定义事件
  - `GalleryFormEditor.vue`：`FormView` 可视化参数配置面板（粒子数/连线距离/配色等）
- **类型适配**：`FormSchema` 是 `{ fields?: FormField[] }` 对象而非数组（初次使用时的常见误区）
- **构建产物**：主 JS 包增至 188.70 KB（+30 KB，主要来自四个模板库的虚拟滚动基座和表单引擎）

## 4. 发现的问题与建议

### 4.1 无 main-ui 缺陷

改造全程未发现 main-ui 缺陷（零破坏承诺兑现）。公开 API 只增不改、持久化自动迁移、主题变量兼容均表现如预期。

### 4.2 改进建议（非阻塞）

1. **view-host-engine 首次使用体验**：`dist/` 产物未预构建时 typecheck 会报类型缺失。建议在 `HOST_INTEGRATION_GUIDE.md` 中补充 "首次接入需先 build 模板包" 的提示，或让各模板包在 `npm publish` 时携带预构建 dist。
2. **p5 桥接的 resize 时机**：p5 实例模式下 `resizeCanvas` 会重置画布内容。建议在 `ExternalEngineApi.onResize` 文档中补充 "宿主引擎应自行处理 resize 后的重绘" 的说明。
3. **FormSchema 类型**：`FormSchema` 是 `{ fields?: FormField[] }` 而非 `FormField[]`，初次使用时容易误传数组。建议在 PRESET_VIEWS_GUIDE 的 view-form 章节补充一个完整的 schema 示例。
